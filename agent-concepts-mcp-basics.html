Agent Concepts and MCP Basics

A 711-word explainer plus live connector evidence: workflow vs. agent, MCP primitives, classification of FL-04, three GitHub tool calls, and one concrete agent upgrade.

Eduardo Seixas Code: FL-05 Client: ChatGPT Connector: GitHub Repository: Eseixas89/ai-evaluation-portfolio

1. Workflow vs. agent

A workflow and an agent can both use language models and tools, but they differ in who controls the path. In a workflow, the sequence is designed in advance. The system knows that step A feeds step B, which feeds step C, and the model mainly performs the work inside those boundaries. In an agent, the model has more control over how the task is completed: it can decide what tool to use next, whether more evidence is needed, whether to repeat a step, and when the stopping condition has been met. Anthropic makes this same architectural distinction: workflows use predefined code paths, while agents dynamically direct their own process and tool use. That distinction matters because agents buy flexibility at the cost of more latency, cost, testing burden, and opportunities for compounded errors.

My FL-04 “Ship an Automation Workflow v2” is therefore a workflow, not an agent. It has five explicit stages: Gather, Source Gate, Synthesize, Draft, and Review + Format. Each stage has a defined handoff. Gather produces candidate sources; Source Gate produces a verified source ledger; Synthesize produces a fact-versus-inference synthesis; Draft turns that into a structured brief; and Review + Format checks traceability and names the remaining human checks. The model does not get to redesign that sequence. That predictability is a feature because the task is recurring and quality-sensitive.

2. MCP in my own words

MCP, the Model Context Protocol, is a standard way for an AI client to connect to external capabilities and context. The three core server primitives are tools, resources, and prompts.

ToolsExecutable functions the model can call, such as reading a repository, querying a service, or writing a file.
ResourcesStructured context exposed to the client, such as file contents, git history, or records.
PromptsReusable templates or instructions exposed by a server for users or clients to invoke.

The important idea is separation of concerns: the model does not need the implementation details of every outside system; it receives a documented interface and can request the capability it needs.

Practical setup used here. I used ChatGPT with the connected GitHub app against my public portfolio repository. This satisfies the assignment's “MCP server or connector” path. I am not claiming that this GitHub connection is a custom MCP server I built; the evidence below demonstrates a working connector using external tool calls.

4. What would make FL-04 an agent?

One concrete upgrade would turn FL-04 from a workflow into a genuine agent: keep the final quality criteria and human approval boundary, but replace the fixed research path with an agentic evidence loop. Give the model the goal “produce a defensible weekly AI-evaluation brief,” access to search and repository tools, a source-quality policy, a maximum action budget, and explicit stopping criteria. The model could then decide whether it needs three searches or twelve, follow a primary source when a secondary source looks weak, revisit an earlier hypothesis when evidence conflicts, and ask for human judgment when it encounters a consequential ambiguity. The final human review would remain.

I would only make this change if evaluation shows that the extra autonomy improves coverage or quality enough to justify the added complexity. For the current recurring brief, the workflow is the better engineering choice; the agent upgrade is useful when the research path itself becomes unpredictable.
