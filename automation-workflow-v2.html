Ship an Automation Workflow v2

A no-code, source-grounded research workflow that turns a recurring AI-evaluation research task into a five-stage pipeline with explicit handoffs, source gating, human review, and a repeatable weekly schedule.

Eduardo Seixas Workflow: Weekly AI Evaluation Brief Tool: ChatGPT Scheduled Task + web research 5 validation runs documented

1. Workflow choice and purpose

I chose a weekly industry brief because it is repetitive, source-heavy, and easy to do inconsistently when handled as a series of one-off prompts. The workflow is designed to produce a concise AI-evaluation brief from current public sources while preserving traceability and a human-review checkpoint.

Working automation. A recurring ChatGPT Scheduled Task is active in my account for Monday mornings (America/Sao_Paulo). The configuration below is the exact instruction used. OpenAI documents Scheduled Tasks as a way to run recurring work such as briefings and deliver the result later; the workflow itself uses only public web sources.

Reference: OpenAI Help — Scheduled Tasks in ChatGPT.

2. Step diagram and handoffs

Step 1Gather
Search 5–8 relevant, recent sources. Prefer primary/official material.
Step 2Source Gate
Remove duplicates, weak sources, and unsupported claims. Build source ledger.
Step 3Synthesize
Cluster evidence, separate fact from inference, surface contradictions.
Step 4Draft
Write Signal, Evidence, Why it matters, and What to watch.
Step 5Review + Format
Trace every substantive claim, flag uncertainty, name human checks.

Defined handoffs: Step 1 outputs a candidate-source set → Step 2 outputs a verified source ledger → Step 3 outputs a fact/inference synthesis → Step 4 outputs a draft brief → Step 5 outputs the final brief plus QA note.

3. Exact configuration used

Create this week's source-grounded AI Evaluation Brief using this five-stage workflow. 1) GATHER: search the public web for 5-8 materially relevant developments from the last 7 days in LLM evaluation, AI quality, model behavior, safety evaluation, benchmarking, human evaluation, or evaluation tooling; prioritize primary sources, official documentation, research papers, and first-party announcements. 2) SOURCE GATE: remove duplicates, weakly sourced items, promotional noise, and claims that cannot be verified; keep a source ledger with title, publisher, date, URL, and the exact claim each source supports. 3) SYNTHESIZE: cluster the retained evidence into 3-5 themes, distinguish fact from inference, note contradictions or uncertainty, and identify what actually changed versus background context. 4) DRAFT: write a concise professional brief with sections Signal, Evidence, Why it matters for AI evaluation work, and What to watch next. 5) REVIEW + FORMAT: check that every substantive factual claim is traceable to the source ledger, flag any unresolved uncertainty, remove unsupported language, and finish with a QA note naming what a human reviewer should still verify. Include source links and do not invent facts or citations.

Schedule: Weekly, Monday morning, America/Sao_Paulo. Input boundary: public web sources only; no private project files are required.

4. Five real validation runs

The same pipeline was exercised on five real AI-evaluation research inputs. Each output below is intentionally concise, but retains the source ledger, decision-relevant synthesis, and human-review requirement.

Validation run

Run 1 - LLM-as-a-Judge reliability

Input. How should I use LLM judges without mistaking scalability for validity?

Signal. LLM graders are useful as scalable first-pass evaluators, but the recurring pattern across sources is that rubric quality, calibration, and human audit matter more than treating a model score as ground truth.

Evidence ledger.
  • OpenAI GDPval — Expert graders remain the reference standard; OpenAI describes its automated grader as a rough estimate and explicitly says it is not yet as reliable as experts.
  • Anthropic Bloom — Judge calibration was checked against hand-labelled transcripts, reinforcing that an automated judge should itself be evaluated.
  • Yamauchi et al. 2025 — An empirical study found that clear evaluation criteria are a critical driver of judge reliability.

Why it matters. For portfolio and production evals, a model judge should be treated as a measurement instrument: define criteria, calibrate on human-labelled examples, monitor disagreement, and escalate ambiguous cases.

What to watch. Cross-lingual consistency, position/verbosity bias, transitivity failures, and drift after prompt/model changes.

Human check. A human must still audit borderline cases, rubric coverage, and whether the metric actually reflects the product goal.

Validation run

Run 2 - RAG evaluation

Input. What is the minimum credible evaluation plan for a RAG system?

Signal. A single end score hides where a RAG system failed. Retrieval quality and answer quality should be measured separately, then connected through groundedness/faithfulness checks.

Evidence ledger.
  • LangSmith RAG evaluation tutorial — Frames RAG evaluation around a test dataset, running the application, and measuring performance with evaluators.
  • Ragas metrics — Provides separate metrics such as context precision, context recall, faithfulness, response relevancy, and noise sensitivity.
  • RAGe 2026 — Extends evaluation toward accuracy-efficiency-resource trade-offs at the pipeline/component level.

Why it matters. When an answer is bad, the team needs to know whether retrieval missed the evidence, ranking was weak, context was noisy, or generation ignored/contradicted the retrieved material.

What to watch. Dynamic corpora, reference-answer quality, metric dependence on LLM judges, and cost/latency trade-offs.

Human check. A human should inspect representative failures and confirm that reference answers and retrieved evidence are actually correct.

Validation run

Run 3 - Prompt injection and agent safety

Input. How should prompt-injection robustness be evaluated for an agent that browses and uses tools?

Signal. Prompt injection is better treated as an end-to-end social-engineering and source-to-sink problem than as a list of malicious strings. Evaluation should test realistic external content plus consequential tool access.

Evidence ledger.
  • OpenAI - Understanding prompt injections — Defines prompt injection as third-party content misleading an AI and recommends layered defenses, explicit instructions, limited access, and user confirmation.
  • OpenAI - Designing agents to resist prompt injection — Frames the problem using social engineering and source-sink analysis for agentic systems.
  • ChatGPT Agent System Card — Documents prompt-injection risk and multilayer mitigations including safety training, monitoring, confirmations, and restrictions.

Why it matters. A useful eval must test whether the agent preserves user intent while encountering untrusted content and whether dangerous actions require appropriate safeguards.

What to watch. Hidden instructions in retrieved pages/files, data exfiltration paths, overly broad permissions, and attacks that only emerge over multiple steps.

Human check. A human must review high-impact action paths, permission scope, and whether confirmations occur before consequential actions.

Validation run

Run 4 - Multimodal evaluation

Input. What changes when evaluation moves from text-only systems to image/audio/vision systems?

Signal. Multimodal evaluation needs modality-specific checks plus cross-modal consistency. Text-only rubrics cannot capture temporal grounding, visual instruction following, audio behavior, or interaction failures between modalities.

Evidence ledger.
  • OpenAI Deployment Safety Hub — Current system cards publish separate safety/capability evaluations for vision, image generation, and voice models.
  • SONIC-O1 2026 — Introduces a human-verified audio-video benchmark with temporal localization and demographic analysis, highlighting failures that static-image tests miss.
  • MMMG 2025 — Uses task-specific evaluation pipelines across image/audio/interleaved generation and reports strong agreement with human evaluation.

Why it matters. Quality can fail in one modality while aggregate performance looks acceptable. Evaluation should separate perception, grounding, temporal reasoning, generation quality, and safety.

What to watch. Temporal grounding, OCR/text-in-image fidelity, cross-modal contradictions, demographic robustness, and automated-judge alignment with humans.

Human check. Humans should review perceptual edge cases and samples where automatic metrics disagree with user-visible quality.

Validation run

Run 5 - Agent evaluation

Input. How should long-horizon AI agents be evaluated beyond final-answer accuracy?

Signal. Agent evaluation has to score the trajectory, not only the final answer. Tool selection, intermediate state, constraint adherence, recovery, side effects, and long-horizon degradation can all fail while the final output still looks plausible.

Evidence ledger.
  • Anthropic - Demystifying evals for AI agents — Recommends combining grader types for agents and evaluating groundedness, coverage, source quality, and task-specific success.
  • Anthropic AuditBench — Finds a tool-to-agent gap: tools that surface useful evidence do not automatically improve agent performance because agents may underuse or misinterpret them.
  • WildClawBench 2026 — Uses hybrid grading with deterministic checks, environment-state auditing, and model judges for realistic long-horizon tasks.

Why it matters. End-to-end reliability requires observing the path: which tools were called, whether parameters were correct, whether state changed as intended, and whether errors were detected and repaired.

What to watch. Tool underuse, context drift, compounding small errors, harness sensitivity, and unsafe side effects.

Human check. A human should inspect representative trajectories, irreversible actions, and cases where graders disagree about whether the goal was truly achieved.

6. Known failure points and required human review

  • Search coverage failure: a relevant paper or announcement may not rank highly. Human check: scan for obvious missing primary sources.
  • Source-quality failure: a polished secondary article can outrank the original material. Human check: prefer first-party documentation or the paper itself.
  • Claim/source mismatch: a source may be relevant but not support the exact sentence written. Human check: verify load-bearing claims against the cited passage.
  • Freshness ambiguity: an old page can be newly crawled or updated. Human check: verify publication/update date when recency matters.
  • Synthesis overreach: the model may infer a trend from too little evidence. Human check: separate fact, inference, and opinion explicitly.
  • Judge/eval circularity: AI-generated summaries about AI evaluation can reproduce the same biases being studied. Human check: audit high-stakes conclusions and disagreement cases.
