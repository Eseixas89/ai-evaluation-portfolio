Learning note / Website infrastructure

From a web address
to a working page.

A website address is easy for a person to remember. DNS helps a computer find the server that can answer it.

What DNS does

DNS, the Domain Name System, connects a hostname such as eseixas89.github.io with information needed to reach its service. An A record contains an IPv4 address; an AAAA record contains an IPv6 address. DNS handles the hostname, not the complete URL: /ai-evaluation-portfolio/ is a path that the web server handles later.

What happens after someone types the address

The browser and operating system may already have a cached DNS answer. Otherwise, they ask a recursive resolver, usually supplied by a network provider or a selected DNS service. If the resolver has no usable cached answer, it follows the DNS hierarchy: root nameservers point it toward the relevant top-level domain; those nameservers point it toward the hostname's authoritative nameservers.

The authoritative nameserver supplies the relevant DNS records. The resolver follows aliases if necessary, returns the address information to the client, and caches it for the time allowed by the record's TTL. Cached information means many visits can skip parts of this lookup. A nameserver answers DNS questions; it does not usually send the website itself.

Where HTTPS and the website response fit

After finding an address, the browser can establish a secure HTTPS connection to the host. TLS checks the server certificate for the hostname and encrypts traffic. The browser then requests the URL's path. GitHub Pages serves this portfolio's index.html; the browser reads it and requests the stylesheet and any other resources needed to display the page.

DNS resolution and HTTPS do different jobs: DNS helps locate the service, while HTTPS protects the connection. A successful DNS lookup alone does not prove that a certificate is valid or that the page exists.

What a CNAME record means

A CNAME makes one hostname an alias of another hostname. For a future custom subdomain, an illustrative DNS configuration would be www.example.com → eseixas89.github.io. The target is a hostname, without https:// or a repository path. The resolver follows the target to find address records; this is not an HTTP redirect and does not itself change the address shown in the browser.

Connecting a custom domain also requires configuration in the hosting service and a valid HTTPS certificate. A CNAME alone is insufficient. This portfolio currently uses GitHub's default domain, so no purchased domain or custom DNS setup is required.
